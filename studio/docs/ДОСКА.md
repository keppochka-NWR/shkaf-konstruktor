## Правила (коротко)
1. **Перед работой** прочитать эту доску и `РЕШЕНИЯ.md`, затем последний раздел журнала другого в Vault: `Vault\Личная система\Проекты\Калькулятор шкафов\Журнал изменений калькулятора.md`.
2. **Ветки короткие**: `claude/<тема>` или `codex/<тема>`, не дольше 1–2 дней, от актуального ствола. Вливает автор сам, когда зелено: `npm test`, `npx tsx scripts/parts-snapshot.ts` → «шкафы без изменений», пакеты сверки кухонь не упали (`scripts/kitchen/batch.ts`), `scripts/kitchen/audit-additions.ts` — 0 добавок сверх Базиса, `tsc --noEmit`.
3. **Код ходит только через git** (ствол на GitHub). Никакого копирования файлов между папками D:/C:/Documents.
4. **Области** — см. таблицу. Чужую область не правим без строки на доске. **Горячие общие файлы** (`App.tsx`, `model.ts`, `pricing.ts`, `KitchenPanel.tsx`, `package.json`): только маленькие правки и только после «заявки» на доске; большие переделки согласуем здесь.
5. **Правила Макса** (обязательны обоим): всё как в Базисе; студия ничего не добавляет сверх Базиса в проекты из Базиса; правила Базиса — только для кухонь (`m.kitchen`), шкафы студии не менять без решения; опоры кухонь не трогать; импорт «как есть» (`m.raw`) — не результат, результат = построено функциями калькулятора и сверено; фамилии и имена клиентских папок — никогда в код, коммиты, документы, тесты; `studio/public/local-projects` не в git; направляющие — комплектами (2 шт.) на ящик; цены клиенту не выдумывать — решения Макса в `РЕШЕНИЯ.md`.
6. **Закончил** — строка на доске (статус, коммит, что осталось) и запись в журнал Vault. **Вопрос Максу** — в раздел «Вопросы Максу», одним предложением с вариантами.
7. **Ревью перед стволом.** Ветка вливается в ствол только после ревью другой стороны: автор пишет на доске «готово к ревью» (ветка, что проверить), ревьюер запускает независимого критика по правилам Макса, тестам и честности заявлений и пишет вердикт на доску. BLOCKING — автор исправляет, повторное ревью. Спорные задачи — конкурс: оба делают в своих ветках, критик сравнивает по одним критериям, Макс выбирает; лучшие куски проигравшего забираются в победивший.
8. **Публикация** на Pages — только общим скриптом `studio/scripts/publish.ps1`; до его появления в стволе вручную не публиковать (прямое решение Макса 14.10). Наличие скрипта в отдельной ветке не означает его приёмку в стволе.

## Как держать связь (Claude, 14.10 — Codex, допиши своё, Макс утверждает)
1. **Одна точка правды — эта доска в git**, не чаты: каждая сторона перед стартом читает доску и последний раздел журнала другого, после финиша — пишет строку. Чаты с Максом — только решения, и они попадают в `РЕШЕНИЯ.md`.
2. **Задача = ветка = строка на доске** с полями «файлы» и «до какого числа». Пересечение по файлам видно до начала работы, а не на конфликте слияния. Строка в «В работе» с перечнем файлов = замок на эти файлы на 2 дня; истёк — файлы свободны, замок продлевают новой датой.
3. **Границы по данным, не по людям**: Codex — помещения/техника/сервер, Claude — конструктив по Базису, смета, тесты, стражи. Горячие файлы (`App.tsx`, `model.ts`, `pricing.ts`, `KitchenPanel.tsx`, `package.json`) — только по заявке и маленькими правками; крупные — через «резку на части» (заявка выше), после неё каждая область получит свой файл.
4. **Ревью крест-накрест перед стволом** (правило 7): критик другой стороны по правилам Макса + тесты. Вливает автор сам после вердикта. Спорное — конкурс.
5. **Машинные стражи вместо договорённостей**: `npm test` по glob (новые тесты подхватываются сами), `parts-snapshot` «шкафы без изменений», `privacy-scan.py --strict` (три источника, 0 совпадений), `audit-additions` 0, `tsc`. Следующий шаг — `studio/OWNERS.md` (карта владения файлами рядом с кодом, те же глобы, что в таблице «Области») и pre-commit `scripts/precommit.cjs`: отказ коммиту с фамилией (privacy-scan по staged) и предупреждение о чужом файле без строки-заявки на доске; сторона определяется по `git config user.name` (`claude` / `codex`).
6. **Публикация одним скриптом** (`publish.ps1`): кто влил в ствол — тот публикует, запись `version.json {commit}` на Pages говорит, что именно опубликовано.
7. **Почта между агентами — раздел «Сообщения» ниже**: короткие адресные записи «кому → что нужно → к какому сроку», получатель отвечает под ней и ставит «прочитано». Ни один из нас не видит чат другого с Максом, поэтому всё, что должен узнать второй, пишется сюда, а не пересказывается Максом.
8. **Ритм дня**: начало сессии — `git fetch`, ветка от свежего ствола, чтение доски; конец — строка на доске, запись в журнал Vault, push ветки. Окно слияний — одно в день, после ревью; две ветки в один ствол за день — только по очереди, второй перебазируется.
9. **Спорное решается данными, не спором**: если оба правы по-своему, делаем конкурс (правило 7) или пишем вопрос Максу одной строкой с вариантами — не ждём молча.
