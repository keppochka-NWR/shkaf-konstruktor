# Кабинет проектов студии

## Локальный запуск
`START-3D.bat` запускает интерфейс на 127.0.0.1:8103 и отдельный API на 127.0.0.1:8104. В студии появилась кнопка «Кабинет». Существующий `server/app.py` и `server/data.db` не используются новой студией.

Хранилище: `server/studio-data.db` (SQLite, в Git не попадает). Таблицы: проекты, неизменяемые предыдущие версии, сессии и одноразовые коды. Архив обратимый. Резервировать БД следует через SQLite backup либо после остановки сервиса, не копировать только основной файл при активном WAL.

Локально включён STUDIO_DEMO=1: вход через три общих тестовых профиля (менеджер, другой менеджер, администратор). Письма не отправляются, реальные адреса не принимаются, API ограничен loopback. Демо не обеспечивает персональную идентификацию сотрудников и не является облачным размещением.

Менеджер сохраняет/открывает свои проекты и архивирует их. Администратор может просмотреть все проекты и сохранить чужой проект собственной копией. Сохранение проверяет revision: устаревшая вкладка получает конфликт, вместо молчаливой перезаписи.

## Зависимости
Python 3.12, зависимости `server/studio-requirements.txt`. Для текущего компьютера они установлены отдельно в `server/.studio-deps`; системный Python не менялся. Исполняемый Python задаётся STUDIO_PYTHON; локальный запуск по умолчанию использует установленный runtime Codex. Для независимой установки использовать собственный Python/venv и установить зависимости из requirements.

## Для внешнего сервера (ещё не выполнено)
Нужны домен/HTTPS, хостинг, почтовый ящик и список сотрудников. Настройки через переменные окружения, не через клиентский код:
- STUDIO_DEMO=0;
- STUDIO_DB — абсолютный путь к закрытой БД;
- STUDIO_ADMINS — адреса администраторов через запятую;
- STUDIO_USERS — разрешённые адреса менеджеров через запятую;
- STUDIO_ORIGIN — точный адрес интерфейса вида https://studio.example;
- SMTP_HOST, SMTP_PORT (465), SMTP_USER, SMTP_PASSWORD, при необходимости SMTP_FROM.

Запуск API: `python server/run_studio.py`; статические файлы `web/` и `/api/studio` должны быть за одним HTTPS-origin. Внешний reverse proxy должен ограничивать тело запроса и частоту запросов. API не раздаёт файлы БД. Cookie HttpOnly, SameSite=Strict, Secure вне демо; код одноразовый на10мин, 5 попыток, 6 запросов/час/адрес. Сессия7дней, выход отзывает её. Адреса вне списка сотрудников не получают доступ. При ошибке SMTP вход не выдаёт код и не переключается в демо.

Внешний деплой, резервное копирование по расписанию, мониторинг и проверка HTTPS/почты пока не выполнены. Сервер хранит JSON-проекты; технологическая валидация остаётся в ядре редактора, серверный выпуск производственных заданий отсутствует.

## Проверки
`python server/test_studio.py` использует временную отдельную БД. Проверены изоляция менеджеров, чтение администратором, конфликт версий, архив/восстановление, выход, CSRF, повторное использование кода, лимит запросов, запрет реальных адресов в демо. Никаких писем тесты не отправляют.
