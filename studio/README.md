# Модуль — 3D-редактор, этап 1

Новый редактор одного прямого корпуса. Старый 2D-редактор сохранён. Исходники — `studio/`, готовая сборка — `web/studio/`.

## Открыть

Двойной клик по `START-3D.bat` в корне проекта. Перейти на http://127.0.0.1:8103/studio/ . Требуется установленный Node.js. Окно запуска должно оставаться открытым. Сборка уже подготовлена: устанавливать зависимости для просмотра не нужно.

При штатном запуске существующего FastAPI-сервера новая страница также доступна по адресу http://localhost:8102/studio/ . В этой работе сервер с рабочей SQLite не запускался, база не изменялась.

## Реализовано

- Вращаемая 3D-модель, зум/пан, виды спереди/сбоку/сверху, вписывание при resize, размеры, разнесённый вид.
- Габариты корпуса; от одной до четырёх секций, изменение внутренней ширины с перераспределением соседей, разделение и удаление секции.
- Полки с индивидуальной высотой и распределением, секции ящиков, штанга, распашные фасады с открыванием.
- 133 декора из каталога Lamarty; для 12 позиций нет изображения в исходном каталоге, интерфейс сообщает об условном цвете.
- Отмена/повтор (до 60 шагов), localStorage с отдельным ключом, JSON-экспорт/импорт. Старые проекты 2D не затрагиваются.
- Единая геометрия для 3D и списка деталей. Постоянные ID корпуса/секций, проверки положительных размеров, границ корпуса, ширины секций, размещения наполнения и полезного формата листа.
- Отзывчивый интерфейс; на узких экранах свойства и библиотека располагаются под моделью.

## Границы версии

Один прямой корпус ЛДСП 16, цоколь 80, ЛХДФ 3. Диапазоны исходного прототипа: ширина 250–1200, высота 400–2200, глубина 250–700; минимальная внутренняя секция 180. Направляющие ящиков — геометрия шарикового варианта; выбор брендов/глубин и полноценная фурнитура впереди. Направления открывания фасадов сейчас фиксированные.

Это редактор, не выпуск производства. Список показывает предварительные готовые размеры, не пильные. Нет расчёта карт, присадки, УП, бирок, облачного сохранения и композиции из нескольких корпусов. Импорт принимает только собственный формат `.module.json`; импорт старого 2D-формата/b3d не реализован.

Проверка полезного поля использует консервативный отступ 10 мм из наработок G code. Это защита редактора, не утверждённый производственный профиль. Кромка и ящики требуют последующей технологической приёмки перед выпуском деталей.

## Разработка

`npm ci` в studio, затем `npm run build`. Каталог автоматически извлекается из существующего `web/assets/catalog-lamarty.js` без закупочных цен. Версии зависимостей фиксированы в package.json и package-lock.json.

`npm test` — проверки расчётного ядра. `npm run test:ui` — браузерные сценарии Playwright/Chrome; должен работать сервер 8103 (`node studio/scripts/serve.cjs`).

Для Vite dev по 5173 каталог доступен, но относительные ссылки текстур требуют выдачи соседней `web/assets` папки. Для полноценной визуальной проверки использовать сборку на 8103.

## Проверка руками

1. Открыть страницу: пример с двумя секциями и наполнением виден сразу.
2. Изменить ширину на 1100 → секции по 526 мм. Высота 3000 отклоняется, остаётся 2000.
3. Отменить/повторить изменение, проверить Ctrl+Z.
4. Выбрать пустой корпус, разделить пополам, задать внутреннюю ширину секции, добавить полку и изменить высоту.
5. Включить фасады, открыть/закрыть; выбрать другой материал корпуса/фасадов.
6. Повернуть модель, проверить виды и разнесение, изменить размер окна.
7. Скачать JSON, перезагрузить страницу, открыть JSON; неподходящий файл не должен заменять модель.
8. Открыть список деталей и сопоставить количество с видимой моделью.

Проверено в ходе реализации: 10 автоматических проверок модели; 3 браузерных сценария (редактирование/хранение/экспорт, секции/плохой импорт, размеры окна/текстуры); ручная проверка обновлённой сборки через встроенный браузер. Контрольные экраны: 1920×1080, 1400×860, 1280×720, 390×844. Численные производственные результаты ещё не сверялись с Базисом.
