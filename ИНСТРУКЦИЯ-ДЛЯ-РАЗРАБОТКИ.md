## 1. Что это и для кого

**Продукт:** 2D-конструктор распашных шкафов и гардеробных для мебельного цеха в Нижнем Новгороде.
Позиционирование: «между Базисом-Мебельщиком и калькулятором». Менеджер задаёт помещение
(ширина стены, высота потолка) и глубину, затем собирает шкаф из модулей «как тетрис».
Конструктор сам ставит петли, фальш-панели, технологические зазоры, считает деталировку,
раскрой, себестоимость, розничную цену и формирует коммерческое предложение (КП).

**Пользователь сейчас:** менеджер цеха. **Потом:** клиент (самостоятельный расчёт на сайте).
Архитектура должна это допускать: никаких «менеджерских» допущений, зашитых в модель.

**Владелец и заказчик:** Макс (владелец цеха). Все конструктивные правила в §5 — его решения
и стандарты цеха. Их нельзя «улучшать» по своему разумению. Если правило кажется странным,
делать как написано и отмечать вопрос в списке «согласовать» (§10.3).

**Ценообразование:** закупочная себестоимость × наценка (по умолчанию 2,2), плюс отдельные
позиции розничного прайса (подсветка), которые добавляются поверх наценки.

Порядок подключения скриптов в `editor.html` важен (глобальные функции, без модулей):
`constants → catalog-lamarty → hardware → lemana → cloud → model → rules → nesting → pricing → render → quote → editor`.
Все ссылки на ресурсы имеют суффикс `?v=N`. **При любой правке JS/CSS увеличивать N во всех
тегах editor.html** (сейчас `v=9`), иначе браузер покажет старую версию.

### 2.2 Запуск локально

Требования: Windows, Python 3.12+ (в проекте `.venv` на 3.13.6), пакеты `fastapi`, `uvicorn`.
Создать окружение, если `.venv` нет:

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install fastapi uvicorn
```

Запуск: двойной клик `ЗАПУСК.bat` или вручную:

```bat
.venv\Scripts\python.exe -m uvicorn app:app --app-dir server --port 8102
```

Открыть `http://localhost:8102/editor.html`. Сервер отдаёт статику с заголовком
`Cache-Control: no-cache` (кроме `/assets/tex`), поэтому правки видны по F5.

Без сервера редактор тоже работает: открыть `web/editor.html` через любой статический
сервер (например `py -3 -m http.server 8102 --directory web`). Тогда облако недоступно,
проекты живут в localStorage. Открытие файла двойным кликом (`file://`) не подходит:
текстуры и fetch не загрузятся.

### 2.3 Режим DEV у сервера

Если рядом с `server/app.py` нет `.env` или в нём `DEV_MODE=1`, код входа не отправляется
почтой, а возвращается в ответе (`dev_code`) и печатается в консоль сервера. Для теста входа:
ввести любой e-mail → взять код из консоли → ввести.

Прод: `.env` с `DEV_MODE=0`, `SMTP_HOST`, `SMTP_PORT` (465, SSL), `SMTP_USER`, `SMTP_PASSWORD`,
`SMTP_FROM`. Деплой планируется как у проекта «Просчитано»: Ubuntu, systemd, Caddy, один воркер
uvicorn (SQLite). VPS ещё не арендован.

### 2.4 Git и публикация

- `origin` = `https://github.com/keppochka-NWR/shkaf-konstruktor.git`, ветка `main`.
- Ветка `gh-pages` = содержимое папки `web/`, публикуется как тестовый сайт. Обновление:

```bat
git subtree split --prefix web -b gh-pages-tmp
git push origin gh-pages-tmp:gh-pages --force
git branch -D gh-pages-tmp
```

- Коммиты писать латиницей-транслитом или по-английски (так сложилось из-за кодировки консоли),
  формат `feat vN: ...` / `fix: ...` / `docs: ...`.
- Секреты и база (`server/.env`, `server/data.db*`) в git не попадают. Закупочные цены в
  `constants.js` и `hardware.js` **публичны** в репозитории. Владелец об этом знает; если
  решит скрыть, репо надо сделать приватным.

### 2.5 Тестов нет

Автотестов в проекте нет. Проверка ручная в браузере по чеклисту §11.0. Любую новую расчётную
функцию (модель, цена, раскрой) желательно сопроводить хотя бы консольной проверкой на
демо-проекте «Прихожая (демо)» из библиотеки (ожидаемая розница 100 400 ₽ при текущих константах).

## 3. Архитектура

Один HTML, глобальная область видимости, без фреймворков, без сборки, без TypeScript.
Слои, строго снизу вверх (верхний может звать нижний, не наоборот):

| Слой | Файлы | Роль |
|---|---|---|
| Данные | constants.js, catalog-lamarty.js, hardware.js, lemana.js | Справочники и константы. Никакой логики, кроме `handlesCatalog()` и `meshCatalog()` (склейка Лемана + база) |
| Модель | model.js | Структура проекта, чистая геометрия в мм, деталировка (`specification`), хранение |
| Правила | rules.js | Можно ли вставить элемент (`canInsert`), предупреждения модуля и проекта |
| Расчёты | nesting.js, pricing.js | Раскрой и цена. Зависят от `specification()` |
| Представление | render.js, quote.js | SVG трёх видов; КП. Не меняют модель |
| Управление | editor.js, cloud.js | События, панель свойств, undo, зум, drag, облако |

Ключевой принцип: **всё вычисляемое не хранится**. Фальш-панели, размеры фасадов, количество
петель, длины направляющих, деталировка — функции от проекта. В JSON проекта лежат только
решения пользователя. Это позволяет менять правила цеха в константах и получать пересчёт
старых проектов.

Главный цикл интерфейса — `update(skipSave)` в editor.js: перерисовать SVG → применить зум →
панель свойств → смета → раскрой → статус → (если не skipSave) сохранить в localStorage,
положить снимок в undo, запланировать автосохранение в облако. Любое изменение модели
заканчивается вызовом `update()`.

## 4. Модель данных (JSON проекта, версия v: 2)

```js
{
  v: 2,
  name: "Шкаф",                 // имя проекта
  room: { w: 3000, h: 2500 },   // стена (ширина), потолок (высота), мм
  depth: 600,                   // глубина шкафа по умолчанию
  plinthH: 80,                  // высота цоколя нижних модулей
  back: "lhdf" | "ldsp",        // задняя стенка: ЛХДФ 3 накладная | ЛДСП 16 вкладная
  bodyDecor: "Белый",           // декор корпуса (имя из LAMARTY[].n)
  facadeDecor: "Белый",         // декор фасадов по умолчанию
  edgeBody: "",                 // цвет кромки 0,4 каркаса; "" = в цвет корпуса
  upperY: 2000,                 // отметка низа верхнего ряда от пола
  markup: 2.2,                  // наценка проекта
  libId, cloudId,               // служебные id библиотеки/облака (могут отсутствовать)
  modules: [ Module ]
}

Module = {
  id: "m3_abc",                 // uid()
  kind: "base" | "upper",       // нижний (на цоколе) | верхний (антресоль, стоит на upperY)
  w: 600, h: 2000,              // габариты модуля, мм (h нижнего включает цоколь)
  depth: null | число,          // своя глубина, null = глубина проекта
  standLight: false,            // подсветка врезная в обеих боковинах
  items: [ Item ],              // наполнение
  facade: {
    system: "none" | "hinge",   // "coupe" зарезервировано под купе
    doors: 1 | 2,
    side: "left" | "right",     // сторона петель при одной двери
    opening: "handle" | "push",
    handleId: null | id,        // из handlesCatalog()
    decor: null | имя           // свой декор фасадов модуля
  }
}

Item = { id, type, y, ... }     // y = отметка НИЗА элемента от низа внутреннего проёма, кратно 16
  type "shelf_adj"   — полка съёмная
  type "shelf_fixed" — полка жёсткая (на конфирматах)
  type "rod"         — штанга D25
  type "drawers"     — секция ящиков: count (шт), boxH (высота ящика), slide: "ball"|"hidden"|"metabox"
  type "mesh"        — сетчатый элемент: meshId (из meshCatalog())
```

Координаты: **все размеры в мм, Y растёт от пола вверх**. Рендер инвертирует (`Y(mm) = roomH − mm`).
Модули одного ряда стоят вплотную слева направо в порядке массива `modules` (позиция X не
хранится, считается `moduleX()`); нижний ряд начинается от `CONST.room.sideGap` (10 мм от стены).
Между рядами `base` и `upper` связи нет, кроме общей отметки `upperY`.

Миграция: `migrateProject(p)` дописывает отсутствующие поля старым проектам. При добавлении
поля в модель обязательно добавить его дефолт в `migrateProject` и в `newProject`/`newModule`.

Хранение: `localStorage["wardrobeProject"]` — текущий проект; `localStorage["wardrobeLibrary"]` —
до 30 проектов менеджера (`libraryList/Save/Load/Delete`); облако — §8.

Геометрические функции model.js, которыми пользоваться (не дублировать):
`modDepth`, `plinthOf`, `moduleX`, `moduleY`, `rowWidth`, `innerBox` (внутренний проём:
w, h, d, x0, y0), `hingeSidesOf`, `itemZone` (вертикальная зона элемента), `fillerPanels`,
`slideInnerW`, `facadeSizes`, `hingesFor`, `slideLengthFor`, `moduleSpec`, `specification`,
`lightMeters`, `edgeMeters`.

## 5. Правила цеха (бизнес-логика). Не менять без владельца

Все числа лежат в `constants.js` (`CONST`) и `hardware.js`. Здесь смысл.

### 5.1 Материалы и корпус
- Плита корпуса и фасадов **16 мм**. Задняя стенка: ЛХДФ 3 мм накладная (деталь `w−4 × h−4`)
  или ЛДСП 16 вкладная (тогда внутренняя глубина уменьшается на 16).
- Корпус модуля: 2 боковины `h × D`, дно и крыша `(w−32) × D`, у нижнего цоколь `(w−32) × plinthH`.
  Цоколь утоплен от линии фасада на 50 (`plinthIndent`), ставится «от переда».
- Полки: глубина `D − 25` (`shelfDepthMinus`). Съёмная — ширина проёма минус 2×1 мм,
  на полкодержателях, шаг перфорации 32. Жёсткая — в ширину проёма, 4 конфирмата.
  Пролёт съёмной полки > 800 → предупреждение о провисании (норматив TODO).
- Кромка: лицевые торцы фасадов 2 мм по периметру, корпус 0,4 мм (`edgeBody` — цвет из
  `EDGE_COLORS`, 20 цветов, которые цех реально закупает у «Победы»).
- Лимиты модуля: ширина 250–1200, высота 300–2200, глубина 250–700 (ТЗ Макса; СТП цеха
  строже, 900×2000, — оставлено 1200×2200 до согласования).
- Зазоры от помещения: по 10 мм с боков (`sideGap`), 30 до потолка (`topGap`), кривая стена −15.

### 5.2 Фасады и петли
- Фасады накладные. Зазор между фасадами 3, по периметру модуля 2. Высота фасада
  `h − plinth − 4`, ширина при двух дверях `(w − 4 − 3)/2` (floor/ceil).
- Фасад шире 600 → предупреждение «тяжёлый». Уже 200 → «неудобное открывание».
- **Количество петель (правило Макса, по весу фасада):** по высоте ≤900 → 2, ≤1600 → 3,
  ≤2000 → 4, выше → 5; **плюс одна**, если ширина фасада > 450. Контрольные точки:
  600×300 → 2, 600×600 → 3, 2000×300 → 4, 2000×600 → 5. Крайние петли на 100 мм от торцов,
  остальные равномерно. Вес фасада показывается как подсказка (11,5 кг/м²).
- Тип петли: с ручкой — GTV с доводчиком (157 ₽), push-to-open — GTV без пружины (80 ₽) +
  толкатель (90 ₽). В цене петли ×2 (`hingeMarkup`) — стандарт калькулятора цеха.
- Ручка: из каталога Лемана (`LEMANA_HANDLES`, настоящие артикулы) или базовый набор цеха (HEXA).

### 5.3 Фальш-панели (важное правило, часто понимают неверно)
Раньше цех ставил широкие фальши. **Сейчас:** фальш = панель 16 мм, прикрученная торцом на
боковину, **только по стороне петель и только в вертикальной зоне выкатного элемента**
(секция ящиков или сетчатый элемент). Без распашного фасада фальшей нет. При двух дверях
фальши с обеих сторон. Высота фальши = высота зоны элемента (`itemZone`), глубина `D − 25`.
Реализация: `fillerPanels()`; фальши не хранятся.

Дополнительно для сетки Лемана: если после фальшей проём всё ещё шире требуемой ширины
изделия (`reqW`) более чем на 4 мм — добавляется «фальш-проставка» до требуемой ширины.

### 5.4 Ящики и направляющие
- Ящики добавляются **секциями**: `count` штук по `boxH`, между ящиками просвет 40
  (`drawerStep`, на направляющую). Зона секции `count × (boxH + 40)`.
- Внутренняя ширина под ящик = проём − фальши (`slideInnerW`). Ширина корпуса ящика =
  она − 2 × `sideDeduct` направляющей: шариковые 13, скрытые 21 (TODO сверить с DTC),
  метабоксы 17 (TODO). Длина направляющей: максимальная из доступных ≤ `D − задняя − 20`.
- Допустимая внутренняя ширина: шариковые 250–1000, скрытые 275–900, метабоксы 300–1200.
  Меньше → отказ с предложением расширить модуль; больше → отказ «провиснет, сузьте или
  добавьте перегородку».
- Закупка цеха: push-to-open скрытые — DTC, с доводчиком — Unihopper; шариковые GTV Versalite.
  Клиентский прайс на направляющие: шариковые 1000/компл, скрытые 1500 (в модели цены пока
  как закупка, см. §10.3).
- Детали ящика (кроме метабокса): 2 боковины `len × boxH`, перед/зад `(boxW − 32) × boxH`,
  дно ЛХДФ `(boxW − 2) × (len − 2)`. Кромка верха 0,4.

### 5.5 Штанги
Труба D25 хром, 300 ₽/м, 2 штангодержателя по 40 ₽. Минимальная высота секции под штангу 900
(TODO норматив), отступ сверху 40. Хранится как элемент с `y`.

### 5.6 Сетчатые системы Лемана Про
`LEMANA_MESH`: корзины, брючницы, обувницы с настоящими артикулами и розничными ценами (парсинг
lemanapro.ru от 01.09.2026). Поля `reqW`, `reqD` — требуемые внутренние ширина и глубина.
Правило вставки: глубина модуля − 5 ≥ `reqD`; ширина: меньше → предложить расширить модуль
до `reqW + (толщины + фальши)`, больше на > 4 → проставка (§5.3).

### 5.7 Подсветка
**Только в боковинах (стойках)**, решение Макса. Флаг `mod.standLight`. Метраж = 2 × высота
проёма. Цена **розничная** 3000 ₽/пог.м, добавляется **поверх** наценки (не умножается).
Подсветку в полках не делать (константа `lightShelfPerM` осталась, не используется).

### 5.8 Раскрой
Лист ЛДСП 2750×1830, ЛХДФ 2800×2070, пропил 4. **Детали не вращаются**: текстура вдоль длинной
стороны листа, деталь кладётся как записана (w вдоль листа, h поперёк). Деталь с меньшей
стороной < 70 → доплата 300 ₽/шт. Группы раскроя: корпус по декору корпуса, фасады по
декору фасадов (у модуля может быть свой), ЛХДФ отдельно.

### 5.9 Цена (pricing.js)
```
себестоимость = листы (кол-во из раскроя × закупка листа по декору, иначе 2900)
              + кромка (2 мм: 45 ₽/м по периметру; 0,4: 15 ₽/м по одному торцу)
              + фурнитура (закупка из спецификации)
              + мелкие детали (300 ₽/шт)
              + работа цеха (2500 ₽ за лист раскроя)
розница = округл_до_100( себестоимость × markup + подсветка_розница )
```
Закупка листов по декорам — `CONST.pricing.ldspSheet` (прайс СФЗ/Победа 01.01.2026).
Владелец обсуждал вариант «лист 23 000 ₽ клиенту» — это розничная экономика цеха, в код не
внесено, значение вопроса не уточнено.

## 6. Деталировка и расчёты — контракт функций

- `specification(project)` → `{ panels: [{mod, part, w, h, qty, edge, material}], hardware: [{name, qty, price}], ldspArea, hwCost }`.
  `material` пустой = ЛДСП 16 декора корпуса/фасада; `"ЛХДФ 3"` = ХДФ. Фурнитура сгруппирована
  по имени. `price: null` = цены нет (в сумму не входит, в КП показывается количество).
- `cuttingPlan(project)` → массив групп `{label, sheetW, sheetH, price, parts, result: {sheets, count, kim, oversize}}`.
  `sheets[].placed` = прямоугольники `{x, y, w, h, label}` для карт раскроя.
- `priceProject(project)` → `{sheets, sheetsCost, sheetsCount, edge, edgeCost, hwCost, feeCost, workCost, light, lightCost, cost, markup, retail, plan, spec}`.
- `openQuote(project, svgEl)` → открывает окно печати с КП; если попап заблокирован, скачивает HTML.
  Возвращает `"window"` или `"download"`.

Новая расчётная логика добавляется в model/pricing/nesting, **никогда в editor.js или render.js**.

## 7. Интерфейс и рендер

### 7.1 Экран editor.html
- Шапка: переключатель видов Спереди/Сбоку/Сверху; поля Стена, Потолок, Глубина, Цоколь,
  Задняя, чекбокс «фасады»; кнопки КП, Экспорт/Импорт JSON, Очистить.
- Слева палитра: «+ Нижний модуль», «+ Верхний модуль»; шаблоны (Платяной, С ящиками, Полочный);
  наполнение перетаскиванием (`draggable`, `data-drag=тип`, для сетки `data-mesh=id`);
  клик по элементу палитры добавляет в выбранный модуль.
- Центр: `<svg id="canvas">` на весь блок; `#dimInput` — плавающее поле инлайн-ввода размеров;
  `#banner` — сообщения с кнопкой действия (например «Расширить»).
- Справа вкладки: Свойства (проект / модуль / элемент / фасад; блок «Облако»; библиотека),
  Смета (деталировка, фурнитура, цена), Раскрой (карты листов, КИМ).
- Строка статуса внизу: предупреждения проекта, состояние облака.

### 7.2 Взаимодействие (editor.js)
- Выбор: `sel = {modId, itemId, face}`. Клик по элементу SVG с атрибутами `data-mod`,
  `data-item`, `data-face`. Клик в пустоту снимает выбор.
- Drag элемента наполнения по вертикали (шаг 16 мм) и модуля по горизонтали (перестановка
  при сдвиге > 60% ширины) — pointer events с `setPointerCapture`. Работает только в виде «Спереди».
- **Кликабельные размеры:** любой размер с атрибутом `data-dim="тип|modId|itemId"` открывает
  `#dimInput`. Типы: `roomW, roomH, upperY, plinth, modW, modH, modD, itemY`. Применение в
  `applyDim`. Критично: на `mousedown` по `[data-dim]` стоит `preventDefault`, иначе фокус
  уходит и поле закрывается; первые 400 мс `blur` игнорируется; Enter ловится по
  `key || code || keyCode` (эмулированные события дают пустой `key`). Не ломать эту цепочку.
- Зум колесом (viewBox), пан правой кнопкой, двойной клик сбрасывает. После зума
  `vbOverride` перекрывает автоматический viewBox до сброса.
- Undo: Ctrl+Z, стек из 60 снимков JSON. Delete удаляет выбранный элемент или модуль.
- Шаблоны создают модуль с готовым наполнением и фасадом (`data-preset`).

### 7.3 Рендер (render.js)
- `renderProject(svg, project, sel, {showFacades, view})` очищает SVG и рисует нужный вид.
  Вид спереди: стена и пол «бесконечными» прямоугольниками (BIG=40000), затем модули
  (`drawModuleFront` → `drawItemFront`, `drawFacadesFront`), цепочки размеров (`chainDims`),
  затем `fitViewBox(svg)` растягивает viewBox под пропорции контейнера.
- Текстуры: `texPattern(decorName)` создаёт `<pattern>` из jpg каталога, `panelRect` кладёт
  текстуру + градиент объёма + контур. Хром штанги, металл сетки, тени — в `buildDefs`.
- Размерные линии `dimH/dimV/dimLabel`; передавать строку `dim`, чтобы размер стал кликабельным.
- Вид сбоку показывает выбранный модуль (глубина редактируется там); вид сверху — план
  ряда (готов под будущие угловые модули).
- Подсветка в стойках рисуется свечением вдоль боковин при `standLight`.

### 7.4 Каталог декоров
`LAMARTY = [{n: имя, cat: категория, tier: ценовая группа, name…, tex: "assets/tex/…jpg" | ""}]`.
Выбор декора в свойствах — сетка плиток с превью текстур (`decorRow`). Имя декора — ключ
всюду (цены листов, кромка), не переименовывать.

## 8. Облако (server/app.py + cloud.js)

Без пароля: вход по одноразовому 6-значному коду на e-mail. Токен сессии (180 дней) хранится
в `localStorage["wcToken"]`, e-mail в `wcEmail`. Проекты хранятся целиком как JSON.

API (все ответы JSON `{ok: true, ...}` или `{ok: false, error, message}`):

| Метод | Путь | Тело / заголовок | Ответ |
|---|---|---|---|
| POST | /api/auth/request-code | `{email}` | `{ok}` (+ `dev_code` в DEV). 422 плохой e-mail, 429 больше 4 кодов в час |
| POST | /api/auth/verify | `{email, code}` | `{ok, token, email}`. 400 неверный (5 попыток), 410 просрочен (10 мин) |
| GET | /api/me | `Authorization: Bearer <token>` | `{ok, email}` / 401 |
| GET | /api/projects | Bearer | `{ok, items: [{id, name, updated_at}]}` |
| POST | /api/projects | Bearer, `{id, name, data}` | upsert, 403 чужой id, 413 > 400 КБ |
| GET | /api/projects/{id} | Bearer | `{ok, name, data}` / 404 |
| DELETE | /api/projects/{id} | Bearer | `{ok}` |

Клиент `window.cloud`: `probe()` (есть ли сервер: 422/429/200 на пустой запрос кода; статический
хостинг даёт 404/405 = облака нет), `requestCode`, `verify`, `logout`, `list`, `save`, `load`,
`remove`, `loggedIn()`. Автосохранение: после каждого `update()` с задержкой 4 с, если вошли и у
проекта есть `cloudId`. Блок «Облако» в панели свойств: `cloudBlock()` в editor.js.

База: таблицы `users`, `codes` (хэш кода, попытки), `sessions` (хэш токена), `projects`
(id текстовый, `user_id`, `name`, `data` JSON, `updated_at`). WAL, один воркер.

## 10. Известные проблемы и открытые вопросы

### 10.1 Баги
1. **Пустой холст после изменения размера окна**: при некоторых пропорциях контейнера
   (наблюдалось при 1400×860) SVG получает высоту больше контейнера (`clientHeight` 1878),
   viewBox вытягивается, чертёж уходит за экран. Причина в CSS `.canvas-wrap`/`#canvas` и
   `fitViewBox`. Нужно жёстко ограничить размер SVG контейнером (`height:100%`, `min-height:0`
   у flex-родителя) и вызывать `fitViewBox` по `resize`.
2. `moduleWarnings` не учитывает фальши при проверке пролёта полки (полка считается на весь проём).
3. `hardware.price` для длин направляющих, которых нет в прайсе (`price[len]`), даёт `null`, и
   позиция не попадает в себестоимость. Нужны цены на все длины или интерполяция.
4. В render.js в виде спереди осталась мусорная строка с `stroke: "#b3a smoke"` (невидимая
   линия, безвредно, удалить).

### 10.2 Технический долг
- Нет автотестов. Минимум: скрипт на Node или в браузере, проверяющий `specification`,
  `priceProject`, `hingesFor` на демо-проекте и на контрольных точках §5.2.
- editor.js на 1000 строк: панель свойств (`renderProps`, ~270 строк) стоит вынести в отдельный файл.
- `catalog-lamarty.js` в одну строку; редактировать только скриптом.

### 10.3 Согласовать с владельцем (не решать самостоятельно)
- Лимиты модуля 1200×2200 (ТЗ) против 900×2000 (СТП цеха).
- Вычеты скрытых направляющих (21/сторона) и метабоксов (17) — сверить с техничками.
- Пролёт съёмной полки 800; минимальная высота под штангу 900; просвет ящиков 40.
- Направляющие в цене: сейчас закупка × общая наценка; у цеха есть клиентский прайс
  1000/1500 за комплект — какой вариант правильный.
- Что означает «стоимость листа 23 000 ₽»: розница листа клиенту вместо расчёта
  «закупка × наценка» или контрольная цифра экономики.
- Публичность закупочных цен в открытом репозитории.

## 11. Очередь задач и критерии приёмки

### 11.0 Регрессионный чеклист (прогонять после каждой задачи)
1. Открыть editor.html, добавить нижний модуль, шаблон «С ящиками», верхний модуль.
2. Кликнуть по жёлтому размеру ширины модуля, ввести 700, Enter → модуль 700, смета пересчиталась.
3. Перетащить полку по высоте; Delete удаляет; Ctrl+Z возвращает.
4. Фасад 2 двери + секция ящиков → в смете появились «Фальш-панель» ×2 высотой зоны ящиков.
5. Фасад 2000×300 → 4 петли; 2000×600 → 5 (ширина фасада, не модуля).
6. Виды Сбоку и Сверху рисуются, глубина модуля правится в виде сбоку.
7. Вкладка Раскрой: листы и КИМ; вкладка Смета: розница = округл_100(cost × markup + подсветка).
8. КП открывается (или скачивается HTML).
9. Библиотека: демо «Прихожая (демо)» загружается, розница 100 400 ₽ (если константы не менялись).
10. С сервером: вход по коду из консоли, «Сохранить в облако», перезагрузка, проект в списке.
11. Зум колесом, пан правой кнопкой, двойной клик сброс; окно другого размера → холст заполнен.

### 11.1 Ближайшие задачи (порядок приоритета владельца)
1. **Исправить баг пустого холста** (§10.1.1). Приёмка: чертёж виден целиком при 1400×860,
   1920×1080, 1280×720 и после изменения размера окна без перезагрузки.
2. **Перегородки внутри модуля** (вертикальные стойки, делящие проём на секции). Модель:
   `mod.dividers: [{x}]` или `mod.sections`; наполнение привязано к секции; `innerBox` и
   `slideInnerW` считают ширину секции; фальши по стороне петель только в крайних секциях;
   деталь «Перегородка» `inner.h × (D − 25)`. Приёмка: модуль 1200 с перегородкой посередине
   принимает ящики на шариковых в обеих секциях; спецификация содержит перегородку; вид спереди
   рисует её.
3. **Угловые модули** (Г-образный шкаф): второй ряд по перпендикулярной стене, угловой
   модуль-стык. Вид сверху уже показывает план ряда. Приёмка: помещение с двумя стенами, модули
   на обеих, размеры по обеим стенам кликабельны, цена учитывает все модули.
4. **Редактор дверей-купе** как `facade.system: "coupe"`: полотно высотой `проём − 40`, ширина
   `(проём + (N − 1) × 22) / N` (перехлёст 22), профиль/направляющие как позиции фурнитуры.
   Формулы и цены брать из калькулятора купе цеха (`Calck claude/projects/kupe`, отдельный репозиторий владельца).
5. **Точный нестинг под ЧПУ**: сейчас гильотина FFDH без вращения. Нужно: учёт текстуры
   (разрешить поворот для однотонных декоров), деловые остатки, экспорт карт в PDF/PNG.
6. **Сборочные чертежи** модулей (виды с размерами, присадка под конфирматы и полкодержатели
   система 32) и **выгрузка на производство**: спецификация + карты + чертежи одним архивом,

7. **Клиентский режим**: упрощённая палитра, скрытие закупочных цен, только розница и КП.

## 12. Шпаргалка: как сделать типовые вещи

**Добавить новый тип наполнения** (например «выдвижная вешалка»):
1. `model.js`: `newItem` — дефолты; `itemZone` — высота зоны; `moduleSpec` — детали и фурнитура.
2. `rules.js`: `canInsert` — ограничения ширины/глубины.
3. `render.js`: `drawItemFront` — отрисовка; при необходимости вид сбоку.
4. `editor.html`: элемент палитры `data-drag="new_type"`; `editor.js`: `itemLabel`, свойства в `renderProps`.
5. `quote.js`: подпись в составе. Поднять `?v=`.

**Добавить константу цеха:** в `constants.js` с комментарием-источником; использовать через `CONST`.

**Добавить декор с ценой листа:** `CONST.pricing.ldspSheet["Имя как в каталоге"] = цена`.

**Добавить ручку или сетку Лемана:** объект в `lemana.js` с `id: "lm<артикул>"`, `art`, `label`,
`price`; для сетки `reqW`, `reqD`, `h`.

**Опубликовать тестовый сайт:** команды §2.4.

**Проверить облако без почты:** запустить сервер без `.env`, код смотреть в консоли.
